# 远程连接手动测试条目

自动化无法覆盖的场景（真实 PTY、真机浏览器、网络切换）。遵循 `docs/测试编写原则.md`，仅记录无法自动化的部分。

> UI 统一化后浏览器端即主应用 UI（TokenGate 认证门 + 完整视图流），下述"手机端/远程端"均指同一套 UI 在浏览器中的表现。

## U UI 统一化（宽屏浏览器 + 手机浏览器）

### U-1 手机宽度整体走查（≤768px）

- **目标**：主 UI 手机断点全流程可用
- **前置**：远程已开启，手机浏览器经 token/配对码连接
- **步骤**：项目页 → 展开近期会话折叠段 → 进入项目 → 新建会话 → 终端输入 → 底部栏开侧边栏抽屉 → 开设置（顶部 tab）
- **预期**：
  - 图标栏变为底部横栏（不遮挡终端，safe-area 生效）
  - 侧边栏为全宽抽屉 + 遮罩，点遮罩关闭
  - 设置页导航为顶部横向滚动 tab
  - 终端字号为桌面设置的 0.75 倍，软键盘弹出时终端自动 fit 不被遮挡

### U-2 桌面/宽屏回归（>768px）

- **目标**：B 端改动不影响桌面布局
- **步骤**：同一账号在桌面 Tauri 与宽屏浏览器（≥1280px）分别走查主流程
- **预期**：图标栏在左侧、侧边栏为 flex 展开（无遮罩）、设置页为左竖导航、终端字号为设置原值

### U-3 真机软键盘

- **目标**：软键盘弹出/收起终端正常
- **步骤**：手机终端点工具条最左侧「键盘」图标唤起软键盘，输入命令；再点该图标（或滚动终端）收起
- **预期**：弹出时 app 高度收缩、终端 fit（PTY resize）、内容不被键盘遮挡；收起后恢复；**点击终端区域不再弹出键盘**（按钮为唯一唤出入口），图标开启态高亮

### U-4 远程开启端口冲突报错

- **目标**：8747 被其他程序（非 CC-Box）占用时，开启远程给出可读错误；被旧版 CC-Box 占用时进入 legacy 降级（不报错，旧版退出后自动接管）
- **前置**：用非 CC-Box 程序占用 8747（如 `python -m http.server 8747`）
- **步骤**：CC-Box 打开远程访问面板并点开启
- **预期**：面板显示含 "failed to bind port 8747" 的错误文案；释放端口后重开面板可正常显示二维码

### U-5 快捷键工具条（手机断点）

- **目标**：软键盘按不出的控制键可用按钮补齐；软键盘由工具条「键盘」图标开关（点击终端不再唤出）
- **步骤**：手机进入终端会话；点击终端输出区域（应无键盘）→ 点工具条最左侧「键盘」图标唤起软键盘 → 再点一次收起；输入时点工具条各键：⇧Tab（切换工作模式）、Ctrl+J（输入多行后一次提交）、Ctrl+U（清空当前输入行）、Esc、↑↓←→（历史与光标移动）、Home/End（行首/行尾）
- **预期**：点击终端区域**不弹出软键盘**（图标为唯一开关，开启态高亮、aria-label 切换为「收起」）；⇧Tab 循环切换 auto-accept/plan 模式指示；Ctrl+J 插入换行不提交；Ctrl+U 清空输入行；↑↓ 翻历史命令、←→ 移动光标、Home/End 跳行首/行尾；滚动终端仍自动收起键盘；工具条无 ^C 按钮；**桌面（hover 设备）不显示工具条——窗口压到 768px 以下也不显示**（手机判定 = 视口 ≤768px 且 `hover: none`）

### U-6 多实例设备级 Gateway（基础链路）

> **2026-10-26 起已改为独立后台 Broker**：不再有 Gateway 选举/成员接管。下文的角色仲裁步骤仅作历史参考；当前多实例行为以 U-18 与 [multi-instance-gateway.md](multi-instance-gateway.md) 为准。

- **目标**：多 CC-Box 实例并存时自动角色仲裁（Gateway/成员），远程不冲突、中继不互踢
- **步骤**：
  1. 实例 A 开启远程（当选 Gateway，占 8747 并连中继），手机扫码连接
  2. 启动实例 B（开启远程），打开远程面板
  3. 关闭实例 A，观察实例 B 与手机
- **预期**：
  - B 自动注册为成员（面板显示成员角色提示 + 与 A 相同的局域 URL，token 设备级共享）；B 不连中继（日志无 relay registered——仅 Gateway 注册，同 device_id 不互踢）
  - A 的面板显示网关角色徽标与成员数
  - A 关闭后 B 自动重选为新 Gateway（日志 `elected as gateway`）并接替连中继；手机自动重连恢复（LAN 重连 8747 / 中继 token 路由不变），无需重扫

### U-6b 多实例远程矩阵（历史：旧 Gateway 选举，已废弃）

> **当前架构以 U-18 为准。** 下文描述的是已删除的 GUI Gateway 选举/角色徽标/重选流程，仅保留作历史参考；不要再按此执行。

- **目标**：多实例分组、跨实例控制、重选恢复与兼容场景全覆盖
- **场景**：

| # | 场景 | 步骤 | 预期 |

| 1b | 同会话跨实例不合并 | A/B 同时恢复同一历史会话（同 sessionId），手机查看列表 | 两个分组各自出现该会话条目（ptyId 不同），互不合并；分别 attach 各走各的实例；分组折叠/展开正常 |

| 6b | 每实例双通道二维码 | 分别在 A（Gateway）与 B（成员）打开远程面板 | 两面板都显示「局域访问」开关；默认公网中继视图显示**同一个**配对二维码（B 经 Gateway 镜像，自身不连 relay）；勾选局域后显示同一设备级 LAN URL（token 共享，扫任一个都连同一入口） |

### U-7 刷新密钥踢掉全部设备（显式轮换）

- **目标**：二维码/配对疑似泄露后，「刷新密钥」一键作废全部访问凭证，所有设备（含自己的手机）必须重新扫码
- **前置**：手机 A、手机 B 均完成配对/扫码连接
- **步骤**：
  1. 桌面远程面板点「刷新密钥」→ 按钮转确认态「确认刷新？所有已配对设备将断开」→ 再点执行
  2. 观察手机 A/B 连接状态
  3. 重新扫码配对手机 A；手机 B 直接用旧凭证重连
- **预期**：
  - 确认后手机 A/B 的连接立即中断；LAN token 与中继设备身份均已轮换（日志 `token rotated` / `device identity rotated`）
  - 手机 B 旧凭证重连被拒（TokenGate「令牌无效」），必须重新扫码
  - 手机 A 用新配对码扫码后正常使用
  - 面板展示新局域码与新配对码
- **回归（停止不再轮换）**：「停止远程→重新开启」后，原已配对手机**无需重扫**即可继续使用（凭证持久，轮换仅由「刷新密钥」触发）

### U-7b 远程访问面板安全说明

- **目标**：面板向用户简要解释安全逻辑（令牌认证/停止即断/刷新密钥作废设备）
- **步骤**：打开远程访问面板（开启态），查看顶部说明文字；切换局域/中继视图再看
- **预期**：说明文字始终可见、不遮挡二维码/按钮操作

### U-8 远程互抢遮罩与接管回来（远程-远程）

> 控制权规则正本见 [protocol.md](protocol.md)「全局控制权」：**attach 不能抢占**，B 须先 `controller.takeover`（全局遮罩上的「接管」按钮）再打开会话

- **目标**：远程端 A 被另一远程端 B 接管后，A 显示遮罩（非断流），可随时抢回
- **步骤**：
  1. 两个浏览器（手机 A / 手机 B 或两个浏览器 tab）连同一桌面，A 打开某会话（A 获得控制权）
  2. B 直接点开同一会话 → 被拒（`session.attach.denied`，attach 不能抢占）
  3. B 点全局遮罩「接管」（controller.takeover）→ 再打开该会话
  4. 观察 A：出现「被其他设备控制中」全局遮罩 + 终端遮罩；遮罩期间 CLI 输出持续同步（订阅保留）
  5. A 点全局遮罩「接管」→ 终端恢复可操作
  6. A 锁屏/断网数秒再恢复（WS 断连重连，服务端分配**新连接 id**）→ A 重新持有/接管后**不应**出现自我遮罩（曾因 selfLabel 旧快照导致重连后自己遮自己、点接管无效）
- **预期**：B 直接 attach 被拒不产生副作用；takeover 后 A 的遮罩与终端归属同步剥离（A 之前 attach 的终端归还桌面后由 B 重新 attach）；A 接管回来后恢复控制权与最新内容（数据层持续同步，无内容缺失/重复；重 attach 的 tail 快照跳过防重复）；互抢对称，桌面端同场景显示相同遮罩；重连后（新连接 id）A 自己持有或接管确认均无自我遮罩

### U-9 刷新/新设备恢复运行中会话

- **目标**：浏览器 Tabs 是内存态，刷新或新设备连接后能回到运行中的会话
- **步骤**：
  1. 手机端打开某项目的运行中会话，刷新页面（或用另一设备连接）
  2. 项目列表：该项目按钮显示运行数徽标；近期会话出现该会话（now/运行中圆点）
  3. 点进项目
- **预期**：Tabs 自动恢复；进入项目后终端自动 attach（无人持有控制权时同时自动获得；他人持有时被拒并显示全局遮罩）并显示 tail 内容；此前未点击的会话不自动 attach（独占语义：点击才接管）

### U-10 attach 运行中会话回放完整（256KB TailBuffer）

- **目标**：attach/订阅一个已产出大量输出的运行中会话，历史内容不丢失（旧 16KB 实现只剩一屏转义序列）
- **前置**：桌面某会话已运行并产出多屏输出（如让 Claude 输出长内容）
- **步骤**：
  1. 手机连接后进入该项目，点开该会话（attach 接管）
  2. 观察回放内容；向上滚动查看更早历史
  3. 另一浏览器 tab 以只读订阅方式打开同一会话（session.subscribe 路径）
- **预期**：
  - attach 后终端立即显示最近约 256KB 输出（数屏历史），可上滚翻阅，无乱码、无内容被抹掉
  - 回放后增量输出正常追加（快照先于增量，无重复/跳变）
  - 只读订阅同样附回放快照

### U-11 会话不重复出现（sessionId 身份链 + 恢复入口复用）

- **目标**：resume 会话被 CLI fork 出新 sessionId 后，会话列表不出现"幽灵"重复条目；任何入口从历史恢复同一对话都复用已有 Tab，不二次 spawn、名字不变编码
- **前置**：手机已连接，某项目有历史会话
- **步骤**：
  1. 手机从历史恢复某会话，发送一条消息（触发 CLI fork 新 sessionId）
  2. 打开会话面板查看历史列表；对比桌面 Tab
  3. 再次从历史列表点击同一会话（含手机端与桌面端各自入口）
  4. 手机刷新页面（adoptRemoteSessions 重建 Tabs）后从历史点击同一会话
  5. 手机关闭该会话后（见 U-14），再从历史恢复
- **预期**：
  - 列表中该会话只出现一份（无 tab + 幽灵历史并存）
  - 再次点击只切换/重启已有 Tab：无新 spawn、无重复 Tab、**名字保持原会话名**（不变 sessionId 编码）
  - 刷新后 Tabs 重建带 sessionId，从历史点击同样复用
  - 关闭后重开：恢复到同一对话（CLI 上下文在），Tab 一份、名字保留

### U-12 复制部分内容（快照阅读器 + 系统选择手柄，手机端）

- **目标**：「选择复制」打开复制阅读器（buffer 快照 + 反渲染），长按唤起**系统原生选择手柄**选范围，复制出的文本无终端渲染引入的假换行/对齐空格
- **前置**：手机已连接并进入某会话，且 Claude 已输出长内容（含多段落与代码块）
- **步骤**：
  1. 点工具条「选择复制」（第二位）→ 全屏阅读器打开，自动滚动到底部（最新输出），软键盘收起
  2. 长按一段正文 → 出现**系统选择手柄**（iOS 放大镜 / Android 原生菜单）→ 拖动手柄调整范围
  3. 点顶部「复制选中」→ 到备忘录/输入框粘贴，核对内容：连续段落无假换行、无对齐空格
  4. 切换「智能 / 原始」模式对比（原始 = 屏幕行原样，智能 = 反渲染段落）
  5. 上下滚动翻阅（快照含全部 scrollback，跨页内容可选）；如内容过长出现截断提示条
  6. 点「复制全部」复制当前模式全文；点「退出」关闭
  7. 退出后回到终端：PTY 未中断，可继续输入；再次进入「选择复制」应抓到最新内容
- **预期**：
  - 阅读器内长按弹**系统**选择菜单（非自定义 UI）；选择仅限正文区（顶栏按钮不可选中）
  - 正文在已有宽度内**自动换行，无横向滚动**（长 URL/路径也强制断行）；智能模式无行尾空格、行内连续空格压缩为单个（终端对齐/填充空格不残留）
  - 智能模式粘贴：段落连续（满宽折行被正确拼接，英文词中断处有空格、中文直拼）、代码块/markdown 结构/diff/表格保留原换行；「复制全部」得到与展示一致的清洗后文本
  - 复制后按钮短暂变「已复制」；空选区时「复制选中」禁用
  - 退出重进快照刷新；终端交互（滚动/点击/键盘按钮）不受影响
- **注意**：须在**生产构建**下验证（main.ts 的 contextmenu 拦截仅 PROD 生效，dev 测不出 Android 长按菜单放行路径）

已知限制（首版接受）：无围栏代码块/表格可能被误拼接（切「原始」兜底）；代码块渲染边框字符（│）暂不剥离；resize 后历史行按当前列宽判断满宽有误差。

### U-13 触摸滚动与软键盘（xterm 6 原生 Gesture）

- **目标**：触摸滚动跟手（像素级 + 惯性）、tap 唤出软键盘并输入、滚动收键盘、无垃圾输入
- **前置**：手机已连接并进入会话，有足够历史输出可翻阅
- **步骤**：
  1. 轻点终端区域 → 软键盘唤出，可输入
  2. 轻点 CLI 输入区某位置（如已输入文本的中间）→ 光标跳转到点击处

  - 轻扫即滚动（无 10px 起手延迟），像素级跟手，带惯性衰减

### U-18 设备级后台 Broker、窗口管理与托盘

- **目标**：一个常驻 Broker 服务整台设备；GUI 只保留 PTY；托盘管理窗口/远程/自启动；零窗口时手机可拉起窗口；崩溃可恢复
- **前置**：Windows/macOS 桌面环境（Linux 托盘当前为无头降级）；已开启远程；手机可扫码

1. **托盘菜单**
   - 右键托盘图标
   - 预期：顶部只有 `CC-Box` 标题（无状态行/数量）；**有新版本时**标题下多一项「更新到 vX.Y.Z」且托盘图标右上角红点；各窗口直接是一级菜单项（不再有「窗口」父级）；之后是「开机自启动 → 新建窗口 → 远程连接 → 刷新远程密钥 → 关闭/开启远程连接 → 退出 CC-Box」
2. **统一远程面板（无主次/无数量）**
   - 启动 GUI A、B、C（顺序不限）→ 打开任一窗口远程面板
   - 预期：三个面板内容一致（同一 LAN/中继二维码、更新连接码/刷新密钥/停止远程三按钮都在）；**不显示“在线实例/窗口数量”或宿主角色**；**不显示开机自启动**（在设置 → 启动）；手机看到 3 个窗口分组，分组名是各窗口的真实标题（项目名/`CC-Box`）
3. **新建/显示窗口（一级项）**
   - 托盘「新建窗口」→ 出现新 GUI 并直接成为一级菜单项；新窗口停在项目列表，不自动进入终端，且**不出现控制台窗口**
   - 窗口名应为该 GUI 的真实窗口标题（打开项目后是项目名；未打开项目时为 `CC-Box`，同名追加序号）
   - 最小化某窗口 → 单击托盘对应窗口项 → 窗口还原并聚焦（无确认）
   - 托盘中**不再提供单窗口关闭/重启**；旧版窗口显示为禁用项
4. **所有窗口关闭后 Broker 常驻**
   - 通过系统窗口按钮关闭 A/B/C（或 `--quit-broker` 退出整体）→ 仅关闭窗口后托盘仍在，`cc-box --broker` 进程仍在；手机连接后列表为空，出现「启动窗口」
   - 手机若停留在终端页且仍有 stopped Tab，也应显示「启动窗口」覆盖层（不要求先返回项目页）
   - 手机点「启动窗口」→ 桌面拉起空 GUI 并注册（停在项目页）；手机随后可新建会话；实例选择器不再提供已下线窗口
5. **Broker 崩溃恢复**
   - 任务管理器结束 `cc-box --broker` 进程 → 存活 GUI 自动重新拉起 Broker 并重注册
   - 预期：手机重连后会话列表恢复；GUI 的 PTY 不中断
6. **停止远程 ≠ 退出 CC-Box**
   - 托盘「关闭远程连接」→ 确认后手机断开，托盘仍在、窗口仍在；「开启远程连接」→ 恢复
   - 托盘「退出 CC-Box」→ 所有窗口关闭、托盘消失；手动重新打开 CC-Box → Broker 重新拉起
7. **开机自启动（设置 → 启动）**
   - 打开 设置 → 启动 → 勾选「开机自启动（后台服务）」→ Windows `HKCU\...\Run` 出现 `CC-Box`；取消后消失（macOS 对应 LaunchAgent，Linux 对应 `~/.config/autostart`）
   - 托盘勾选状态与设置页一致；远程面板**不应**出现该开关
   - 带 `--broker --autostart` 启动时，即使上次是「退出 CC-Box」也会启动 Broker，且不自动开窗口；Linux 无托盘时用设置页操作
8. **`--quit-broker`**
   - 命令行执行 `cc-box --quit-broker` → 所有窗口关闭、Broker 退出；无 Broker 时返回非零并提示
9. **LAN 端口被第三方占用**
   - 用其他程序占 8747 后重启 Broker → 面板提示「局域网不可用（中继仍可用）」，中继二维码可扫码控制
10. **旧版 Gateway 占口**
    - 先启动旧版 CC-Box（占 8747）再启动新版 → 新版面板提示旧版占用，不展示旧版二维码为完整设备入口；退出旧版后新版自动接管。旧版窗口在托盘中显示为禁用项（无法显示/控制）
11. **创建后立即 attach**
    - 手机在某个窗口新建会话，创建成功回调后立即点开会话 → 终端正常 attach，无「会话不存在」
12. **输入拥塞/输出缺口**
    - 让会话持续输出大量内容并快速输入 → 输入不静默丢失；若输出被丢弃，终端出现「输出中断：跳过 N 段」提示
13. **更新期间**
    - 在设置中下载并安装更新 → Broker 关闭除发起窗口外的其他窗口，写 `update_in_progress` 后退出释放 exe；发起窗口继续安装/重启；同一版本重试 5 分钟内不反复拉起
14. **远程连接 / 刷新密钥 / 关闭远程连接**
    - 托盘「远程连接」→ 第一个窗口还原/聚焦并弹出远程连接面板；零窗口时先新建一个窗口再打开面板（无确认）
    - 托盘「刷新远程密钥」→ 弹出确认对话框（提示所有已配对设备将断开）；确认后执行，取消则不执行
    - 托盘「关闭远程连接」→ 弹出确认对话框（提示手机会断开、后台服务继续运行）；确认后 LAN/relay 停止，取消则不执行
    - 远程关闭状态下该菜单项变为「开启远程连接」，点击直接执行（无确认）
15. **窗口标题同步**
    - 在窗口 A 打开项目 `foo` → 托盘窗口名变为 `foo`，手机分组/实例选择器同步变为 `foo`；切回项目列表后窗口标题恢复 `CC-Box`；窗口 B 再打开同名项目 → 显示 `foo` / `foo (2)`
16. **跨窗口状态同步**
    - 在窗口 A 修改 provider/config/skill 开关 → 窗口 B/C 的对应面板无需手动刷新即更新（成员 `state.changed` 上行 → Broker 扇出）
17. **控制权边界**
    - 未 attach 的手机直接发送 `pty.input`（正常 UI 不会触发）→ 不应取得全局控制权；桌面/其他设备仍可操作

18. **托盘更新提示**
    - 发布一个新版本（latest.json 版本号高于当前）→ 等 Broker 下一次检查（启动后 30s / 每 2h；重启 Broker 可立即触发）
    - 预期：托盘图标右上角出现红点，菜单标题下出现「更新到 vX.Y.Z」；点击该项 → 显示第一个窗口并跳到设置 → 更新，自动检查出可用版本；无窗口时先拉起一个新窗口
    - 完成更新并重启后红点与菜单项消失（已是最新）

## R2-7 全局控制权（设备互斥）

- **目标**：同一时间只有一个设备可操作——**桌面与所有远程设备对等参与**；控制权由服务端裁决，前端只展示（ControllerMask 全局遮罩）
- **前置**：两台设备（或两台手机/手机+宽屏浏览器）A、B 均经 token/配对连接；桌面有运行中会话
- **步骤与预期**：
  1. **自动持有**：A 点进会话（attach）→ A 获得控制权；B 与**桌面**整界面出现"被其他设备控制中"遮罩 +「接管」按钮；B 直接点会话无法进入（attach 被服务端拒绝）
  2. **写操作被拒（服务端兜底）**：B 在遮罩期间绕过 UI（DevTools 手动发 rpc.call set_skill_enabled）→ 收到 "controller held by another device" 错误
  3. **接管转移（远程）**：B 点「接管」→ B 遮罩解除并全量刷新（会话列表重拉、终端重 attach 带回放）；A 出现全局遮罩，A 之前 attach 的终端被剥离（终端遮罩同步解除、尺寸恢复桌面 fit）
  4. **接管转移（桌面）**：桌面点遮罩上的「接管」按钮（或终端「接管回来」）→ 桌面获得控制权并剥离远程终端归属；A/B 出现全局遮罩；**桌面普通操作（点面板/切 Tab/改设置）不触发接管**——远程持有不受影响
  5. **接管回来**：A 点「接管」→ 控制权回 A，循环往复无死锁
  6. **断连释放**：A 持有时杀掉 A 的浏览器/飞行模式 → B/桌面遮罩自动消失（广播空 controller）
  7. **无风暴回归**：页面加载后桌面日志无 update_app_config 高频重试（曾因 loadAppConfig 写回死循环导致 rpc 超时与 config.json 损坏，回归必测）
  8. **中继模式**：手机经中继连接重复 1-7（同一套 handler；中继与直连各验一轮）

## R2-8 写命令状态广播（state-changed）

- **目标**：任一端的写操作（开关/Provider/配置）全端 UI 即时一致
- **步骤**：
  1. 手机开 Skills 面板关掉某 skill → 观察桌面 Skills 面板（提前打开）
  2. 反向：桌面开 Plugin → 观察手机 Plugins 面板与 skills/agents/mcp 子项
  3. 手机 Provider 面板激活另一 provider → 观察桌面 Provider 列表
  4. 编辑保护：桌面打开 Provider 编辑面板（有未保存修改）→ 手机激活 provider → 桌面编辑内容不被覆盖；关闭编辑面板后列表补刷
- **预期**：各端对应面板约 1s 内刷新为新状态（无需重开面板/项目）；编辑中表单不被远程变更直接覆盖

## R3 公网中继

### R3-1 中继部署与接入

- **前置**：VPS 按 [deploy.md](deploy.md) 部署 cc-box-relay + nginx 子域 + 证书
- **步骤**：桌面远程弹窗 → 中继区填 `https://<中继域名>` → 连接
- **预期**：显示"中继已连接"与配对二维码（约 2s 内出现）

### R3-2 手机配对一次长期有效

- **步骤**：手机（任意网络）扫中继配对码
- **预期**：
  - 打开中继页面自动完成配对并进入会话列表
  - 关闭浏览器再开（含切 Wi-Fi/流量）打开即连，无需重新扫码
  - 桌面 config.json 的 `remote.pairedSecrets` 出现该设备的 secret（首次连接时固化）

### R3-2a 中继重启后手机自动恢复（token v2）

- **目标**：relay 无凭证存储、token 校验在桌面——重启不再强制全员重配对
- **步骤**：手机配对并 connected → 重启中继（本地 `Ctrl+C` 后重新 `cargo run`；生产 `systemctl restart cc-box-relay`）
- **预期**：
  - 手机短暂显示「重连中」，桌面日志出现 `relay disconnected → relay registered`
  - 手机在两端退避窗口内（数秒至约 1 分钟）**自动恢复 connected，无需重新扫码**
  - 恢复后会话列表/终端接管功能正常

### R3-2b 伪造 token 被桌面拒绝

- **目标**：relay 只路由不校验，secret 校验闭环在桌面
- **步骤**：手机 TokenGate 手动输入 `<真实 device_id>.<32位伪造hex>` 格式的 token 连接
- **预期**：收到「令牌无效」被拒（hello.error，停止重连）；重新扫码可正常配对

### R3-3 公网完整功能

- **目标**：中继模式下 R2 全部功能可用
- **步骤**：手机经中继接管会话、输入、新建、关闭
- **预期**：与局域网直连行为一致（同一套应用层 handler）


### R6-6 桌面显式关闭会话，远程"打开的标签页"联动移除

- **目标**：桌面 closeTab（含关闭全部/其他）后，远程浏览器端 Tab 从"打开的标签页"移除，不残留"已停止"条目
- **步骤**：远程浏览器打开会话 Tab → 桌面端关闭该 session
- **预期**：远程端 Tab 即时从列表消失（remote-session-closed 先于 pty-exit 到达）；自然退出（CLI 内 /exit）仍保留 Tab 显示已停止

### R6-7 被接管期间桌面窗口可拖动

- **目标**：全局控制权遮罩不阻挡 TitleBar 窗口操作
- **步骤**：远程设备接管 → 桌面出现遮罩 → 拖动标题栏/点最小化
- **预期**：遮罩期间 TitleBar 仍可拖动窗口、最小化/最大化/关闭可用；业务区仍被遮罩

### R6-8 浏览器标签页标题为项目名

- **目标**：远程浏览器模式 document.title 跟随当前项目
- **步骤**：浏览器打开项目 A → 切换/另开标签页进入项目 B
- **预期**：浏览器标签页标题分别显示 A/B 项目名（桌面 Tauri 窗口标题不受影响）

### R7-9 远程文件上传/下载（FilesPanel）

- **目标**：浏览器远程模式经 rpc 分块命令与桌面互传文件（无专用协议消息）
- **步骤**：手机上传文件 → 验证落盘项目 `.cc-box-files/` + 终端插入路径；浏览项目内文件下载到手机
- **预期**：512KB 串行分块（中继消息 <4MiB）；路径含空格加引号；上传中切换终端不串插；同名自动 `(n)` 改名不覆盖

### R7-10 文件传输限额与安全边界

- **目标**：双限额（直连 200MB/中继 20MB 可配置）与授权项目白名单
- **步骤**：中继上传 30MB（拒）→ 直连同文件（过）；手输项目外路径下载（拒）；另一设备持控制权时上传（拒 → 接管后过）
- **预期**：限额按「经由中继」判定（relay 桥接 true / 直连 false，服务端注入不可伪造）；白名单外路径 list/download 均拒；断流后 `.upload-*.part` 被 TTL/启动清理
