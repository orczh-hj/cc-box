# CC-Box 自动更新设计（2026-10-31）

## 意图

让 CC-Box 在无人值守时自动升级：开机自启的 Broker 在后台静默更新到最新版，用户打开 GUI 时大多已是新版本。手动更新入口从「跳设置页」简化为托盘菜单直接执行。

## 用户可见行为

- **设置 → 更新 → 更多设置（折叠）**新增「自动更新」开关，默认**开启**，存 `~/.cc-box/config.json`（GUI 与 Broker 共享读写）。
- **托盘菜单**：
  - 有新版本 → 显示「更新到 vX.Y.Z」，点击 → 原生二次确认 → Broker 直接下载+安装+重启（不再跳 GUI 设置页）。
  - 无新版本 → 显示「检查更新」，点击立即检查一次并刷新菜单结果。
- **托盘红点**：缩小（半径 0.28 → ≈0.16），圆心更贴右上角边缘。
- GUI 设置页的手动更新流程保持不变。

## 自动更新逻辑（Broker 侧单点）

触发时机（仅两处，均要求「自动更新」开关开启）：
1. **Broker 启动即刻检查**（不等 30s）。
2. **每 2h 周期检查**（保持现有节奏）。

统一流水线：**下载 → 判断有没有窗口 → 安装**（下载与安装解耦）：
- 检查到新版本 → **无论开关是否开启、无论是否有窗口，都自动下载**并保留已下载的更新（例如启动时用户正在用，先下好；关了自动更新的用户点托盘「更新到 vX」也能即点即装）。
- 安装条件在每次检查时评估：**自动更新开关开启 && 新版本已下载好 && 当前零 GUI 窗口** → 安装 → 写 `update_in_progress` → 重启自身 → 版本变化后解除标记。
- 若检查时仍有窗口（或开关关闭）：已下载的结果保留，等**下次检查**再看，下载不重复。
- 安装/重启失败：清 `update_in_progress`、恢复 Broker（复用现有失败恢复路径）。

托盘「更新到 vX」手动更新走同一条流水线（此时有窗口也安装：用户已二次确认，先让窗口整体退出再安装）。

## 目标 / 非目标

- 目标：零窗口与开机自启场景自动升级；检查到新版本即预下载（与开关无关），安装等开关开启且零窗口；托盘一站式手动更新；可一键关闭。
- 非目标：有窗口/有会话运行时自动更新（杀正在跑的 Claude 会话不可接受）；GUI 内嵌自动更新逻辑（保持 Broker 单点）。

## 实现要点

- `src-tauri/src/broker/update.rs` 扩展：`spawn_checker` 启动即查、保留 2h 循环；实现「下载 → 判窗口 → 安装」统一流水线（下载结果跨检查保留，tauri updater 插件 Broker 无窗口可用）；自动安装前判 `gateway::window_roster()` 为空；托盘手动更新复用同一条流水线（有窗口时先让窗口整体退出再安装）。
- `src-tauri/src/broker/tray.rs`：`build_model` 增加「检查更新」项（无更新时）；「更新到 vX」点击改为二次确认后调用同一执行链；`badge_icon` 红点参数调整并抽为纯函数可测。
- 配置：`store.rs` AppConfig 增加 `autoUpdate`（默认 true），GUI 设置页开关读写该字段；Broker 直接读共享 config。
- 事件/i18n：新增文案走 i18n（zh/en 两份）。

## 测试

- `build_model`：无更新时出现「检查更新」、有更新时出现「更新到 vX」。
- 红点纯函数：半径/圆心按新参数断言。
- 自动更新决策（抽纯函数状态机）：开关关（只下载不装）/未下载/已下载+开关开+有窗口（不装）/已下载+开关开+零窗口（装）/失败恢复。
- 前端：设置开关读写 config 的 store 测试。

## 方案取舍

- 备选 A：安装决策由「下载完成后监听窗口清空」即时触发——被否，遵循「下次检查时再看」的明确要求，且避免新增监听路径。
- 备选 B2：仅零窗口才下载——被否，用户要求检查到即预下载，安装时机等零窗口。
- 备选 B：GUI 侧执行自动更新——被否，零窗口场景 GUI 不在，Broker 是唯一常驻方。
